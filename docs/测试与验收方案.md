# 灵犀采购 · 测试与验收方案

> 本文档是项目测试体系的"总说明书"：怎么分层、怎么跑、验什么、通过标准是什么。
> 面试被问"你这项目怎么保证质量"时，按本文档讲即可。

---

## 1. 测试分层（金字塔）

| 层 | 标记 | 数量 | 依赖 | 耗时 | 何时跑 |
|---|---|---|---|---|---|
| 单元测试 | `unit` | 37 | 无（纯函数/校验器） | 秒级 | 每次改代码、CI 每次提交 |
| 集成测试 | `integration` | 16 | MySQL（Redis 可选） | ~8 秒 | 每次提交 |
| 端到端验收 | `e2e` | 8 | 真实 LLM + 全套服务 | 分钟级 | 发版/演示前 |
| 手工 UAT | — | 8 项 | 浏览器 | ~5 分钟 | 发版前 |

**核心原则**：
1. **LLM 一律不进单测**——非 e2e 用例由 conftest 全局拦截真实 LLM 调用，测试结果确定、零 token 成本；
2. **红线逻辑不信任 LLM**——预算红线、底价判定、SQL 安全闸全部是程序代码，全部参数化覆盖边界值；
3. **失败可分层归因**——unit 挂 = 逻辑错；integration 挂 = 数据/接线错；e2e 挂 = 链路/LLM 错。

## 2. 运行方式

```bash
pytest -m unit              # 单测（毫秒级，CI 必跑）
pytest -m integration       # 集成（需 MySQL）
pytest -m e2e               # 端到端验收（需先启动后端 8001）
pytest                      # 全量
pytest --cov=src            # 覆盖率（HTML 报告在 reports/coverage/index.html）
```

### 测试驱动修复记录（真实 bug 案例）

`test_level3_fallback_to_db_when_offline` 首跑即发现：`fetch_realtime_price` 抛出**非预期异常**时（akshare 升级改 API、SSL 错误等），异常会穿透 `refresh_market_price` 直接炸到接口层 500——原代码只兜了"返回 None"的情况。已在 `market_provider.py` 第 2 级补 try/except，实时级任何异常一律转降级读库。这是"断网演示不中断"承诺的实证修复。

## 4. 专项测试设计（面试重点）

### 4.1 预算红线（`test_validators.py`，16 用例）
- 参数化边界：`total == budget` 放行 / `total == budget + 1` 拦截；
- 防误杀：总价被预算钳制产生的低价（`total == budget` 时单价 < 基准价一半）是诚实的预算约束，不判异常；
- 契约测试：校验器只读不改 state（防止校验本身成为副作用源）。

### 4.2 NL2SQL 安全闸（`test_nl2sql_guard.py`，9 用例）
模拟"提示词注入诱导 LLM 写出恶意 SQL"，验证**程序侧**三道闸：
- 只认 SELECT 开头；写操作词黑名单（drop/delete/truncate/alter…）；
- 无 LIMIT 自动补 `LIMIT 20`（防拖库）；
- 总入口 `run_nl2sql` 任何失败转 `{"error": ...}`，绝不炸问答子图；
- **已知边界诚实记录**：纯 `UNION SELECT` 跨表探测当前放行（有专门用例文档化，缓解措施：SCHEMA 白名单 + 只读账号），后续加固方向为表名白名单解析。

### 4.3 行情三级接力（`test_market_provider.py`，5 用例）
monkeypatch 模拟「缓存命中 / 实时成功 / 断网 / 库里也没有」四种环境，断言：缓存命中不联网、实时成功必须写库留痕、断网降级读库、全空时诚实返回"无数据"不编造价格。

### 4.4 集成层契约（`tests/integration/`，16 用例）
- 错误码契约：4001（非法参数）/ 4002（状态机不允许）/ 4004（查无此单）；
- **红线不篡改**：任务落库后 `budget_limit` 与写入值 Decimal 级精确相等；
- 删单后 GET 必 404（级联删除生效）。

## 5. e2e 验收（对照 PRD §4.1~§4.5）

`tests/e2e/test_full_flow.py`，每条对应 PRD 一个验收面：

| 用例 | 验收点 |
|---|---|
| 分支B 合理预算 | 正常跑完 + 方案 >500 字 + 成交额落库 + 预算红线无篡改 |
| 分支A 恶意低预算 | 必须终态 blocked（拦截分支） |
| 谈判留痕 | negotiation_log 轮次 ≥1（复盘/审计能力） |
| Checkpoint | Redis 中存在 thread_id=task_id 的恢复键 |
| RAG 溯源 | 回答必须带 sources |
| NL2SQL 溯源 | 含真实订单号或 SQL 凭证（防幻觉） |
| 前端+接口可达 | 5 个 URL 全 200 |
| 工程化 | 降级/重试/合规种子数据在位 |

## 6. 手工 UAT 清单（发版前 5 分钟动线）

1. 打开 `http://127.0.0.1:5174`：三张图有真数据、灵犀仔冒泡、任务列表在；
2. 行情切「铜材」「铝材」→ 曲线切换正常，右上角"数据截至"徽标正确（实时绿/缓存青/降级橙）；
3. 供应商切「天津市」→ 排行只剩天津企业，条尾有溢价率；

6. 悬浮助手问「查一笔历史订单的金额」→ 打字机输出 + 来源卡片含真实订单号；
7. 刷新页面 → 方案面板与任务列表自动恢复（localStorage + 落库双保险）；
8. 断网重演：关外网后切行情品种 → 页面仍出数据（降级读库），徽标变橙。
